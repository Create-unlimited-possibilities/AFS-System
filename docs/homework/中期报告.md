# Abstract

This project presents "传家宝 (AFSS)" - an Artificial Fluctlight Simulation System designed to create virtual replicas of terminally ill elderly for emotional companionship. The system addresses the universal human need to preserve memories and maintain emotional connections across generations.

The core innovation of AFSS lies in its three-module architecture:
1. **Fate Replicator** - A Zi Wei Dou Shu (Purple Star Astrology) expert model that infers complete life destiny trajectories from minimal information (birth data + questionnaire)
2. **Memory Arbor** - A memory fusion system that integrates real memories (diaries, interviews) with conversational memories using forgetting curve algorithms
3. **Fluctlight Core** - A lightweight Five Aggregates framework that simulates personality and emotional variation for authentic interactions

The Fate Replicator module has been fully trained and achieves 96% accuracy in palace interpretation, enabling the system to understand users at a deep personality level. The system uses DeepSeek R1-14B as the primary LLM with LangGraph multi-agent orchestration for conversation management.

The system is built with a modern tech stack: Next.js 15 frontend with TypeScript and Tailwind CSS, Express.js backend with Controller-Service-Repository architecture, MongoDB and ChromaDB for data storage, and Docker containerization for deployment. The AI services leverage Ollama with Unsloth LoRA fine-tuning.

This interim report details the project background, problem analysis, technical framework, implementation progress, and the roadmap for Phase II development.

# 1. Introduction

## 1.1 Background and Motivation

### 1.1.1 The Universal Need for Memory Preservation

Throughout human history, the preservation of memories and life stories has been a fundamental need across all cultures. Every individual accumulates a unique collection of experiences, wisdom, and personal narratives that define who they are. For the elderly, these memories represent not just personal history, but a legacy they wish to pass on to future generations.

### 1.1.2 The Growing Challenge

As global populations age, an increasing number of elderly individuals face the prospect of their life stories being lost forever. Traditional methods of memory preservation—photo albums, written diaries, and oral storytelling—while valuable, have significant limitations:

- **Static Nature**: Photos and diaries capture moments but lack interactivity
- **Limited Accessibility**: Physical records can be lost, damaged, or difficult to access
- **No Dialogue**: Traditional records cannot respond to questions or share new perspectives
- **Emotional Disconnect**: Static memories cannot provide comfort through active conversation

### 1.1.3 The Pain of Loss

When a loved one passes away, family members often experience profound grief compounded by the realization that they can no longer:
- Ask for advice from someone who knew them best
- Hear comforting words in a familiar voice
- Share new experiences with someone who would care most
- Continue learning from a lifetime of accumulated wisdom

This emotional void creates a genuine need for technology that can preserve not just memories, but the essence of a person—their personality, speech patterns, values, and unique way of expressing love.

### 1.1.4 The AI Opportunity

Recent advances in Large Language Models (LLMs) and AI technology present an unprecedented opportunity to address this need. Modern AI systems can:
- Learn and mimic individual speech patterns
- Understand and respond with emotional intelligence
- Maintain consistent personality across conversations
- Integrate complex knowledge systems for deeper understanding

### 1.1.5 The Role of Traditional Chinese Astrology

Zi Wei Dou Shu (紫微斗数), or Purple Star Astrology, is one of the most sophisticated systems of Chinese metaphysics with over a thousand years of history. It provides deep insights into an individual's:
- Core personality traits and tendencies
- Life patterns and potential destiny
- Strengths and challenges across different life domains
- Interpersonal dynamics and relationship patterns

By integrating this ancient wisdom with modern AI, we can create character cards that truly "understand" the elderly person at a fundamental level, enabling more authentic and meaningful interactions.

# 2. Problem Analysis and Proposed Solution

## 2.1 Problem Analysis

### 2.1.1 The Memory Loss Problem

As elderly individuals age, they face the gradual loss of their ability to share their life stories and accumulated wisdom. This represents a significant loss for both the elderly person and their families:

- **Progressive Memory Decline**: Age-related cognitive changes can affect the ability to recall and articulate memories
- **Limited Documentation Time**: The window for capturing authentic life stories is finite
- **Family Knowledge Gaps**: Children and grandchildren often realize too late that they never asked important questions

### 2.1.2 The Emotional Companionship Gap

When elderly family members pass away, their loved ones experience:

- **Grief and Loss**: The absence of a familiar voice and presence
- **Unfinished Conversations**: Questions that were never asked, stories never fully explored
- **Emotional Void**: The loss of someone who understood and comforted them

### 2.1.3 The AI Understanding Barrier

Traditional AI chatbots and conversational agents suffer from a fundamental limitation:

- **Generic Responses**: Without deep understanding of user personality, responses feel impersonal
- **No Life Context**: AI cannot reference shared memories or understand family dynamics
- **Shallow Empathy**: Without understanding a person's character, empathy feels artificial

## 2.2 Problem Statement

**How can we create an AI system that:**

1. **Captures Authentic Memories**: Collects and preserves elderly individuals' life stories in their own voice
2. **Enables Posthumous Companionship**: Allows children to continue meaningful conversations after their loved ones have passed
3. **Deeply Understands Users**: Leverages personality analysis to provide genuinely empathetic and personalized responses

### 2.3.4 Gap Analysis

No existing solution successfully combines:
- **Proactive memory collection** through natural conversation

- **Personality analysis** using traditional Chinese wisdom (Zi Wei Dou Shu) to enhance AI understanding

# 3. Data Analytical Framework

## 3.1 Data Acquisition and Understanding

### 3.1.1 Data Sources

Our system utilizes multiple data sources to create comprehensive user profiles and enable intelligent AI responses:

| Data Source | Type | Purpose | Collection Method |
|-------------|------|---------|-------------------|
| **User Profile** | Structured | Basic information, birth data | Registration form |

### 3.1.2 Data Volume

| Data Category | Volume | Storage |
|---------------|--------|---------|
| Classical Zi Wei texts | 5 Word documents (~1.2M chars) | books/ directory |
| Text chunks | ~2,000-4,000 chunks (300-600 chars each) | FAISS index |
| Vector embeddings | 384-dim × chunk count | data/vectorstore/ |
| SFT training samples | 200-800 ChatML samples | data/dataset.jsonl |
| LoRA adapter weights | ~50-100MB | models/hf/fine_tuned/ |
| GGUF quantized model | ~7-9GB (Q4_K_M) | models/gguf/ |
| User memory database | Growing | MongoDB + File system |

**Classical Book Sources:**
The training data includes 5 authoritative Zi Wei Dou Shu classical texts:
1. 紫微斗数全书 - Comprehensive system overview
2. 紫微斗数讲义 - Teaching materials
3. Additional classical interpretations for specific palace/star combinations

### 3.1.3 Data Quality Assurance

**For Zi Wei Dou Shu Training Data:**

| Quality Measure | Implementation |
|-----------------|----------------|
| Classical Text Verification | Manual proofreading after Word extraction |
| Chunk Quality | 300-600 char chunks with 50-100 char overlap |
| Source Attribution | Every chunk tagged with book name + location |
| Embedding Consistency | Single model (all-MiniLM-L6-v2) for all chunks |
| Retrieval Validation | Top-K threshold filtering (similarity > 0.7) |

**RAG Module Processing Pipeline:**
1. **Text Extraction**: python-docx extracts paragraphs from .docx files
2. **Cleaning**: Remove headers, footers, excessive whitespace
3. **Chunking**: Split by paragraph boundaries, maintain context overlap
4. **Embedding**: Generate 384-dim vectors with sentence-transformers
5. **Indexing**: FAISS FlatIP index for exact similarity search
6. **Retrieval**: Query → Vector → Top-K chunks → Context assembly

**For User Memory Data:**
- Confirmation prompts during collection
- Family member verification option
- Duplicate detection and merging

## 3.2 Data Models / Algorithms

### 3.2.1 Zi Wei Dou Shu Chart Calculation

The chart calculation engine is implemented using **py-iztro** (v0.3.3), an open-source Python library that faithfully reproduces traditional Zi Wei Dou Shu algorithms. The module is designed with a clear separation of concerns: calculation logic is completely isolated from interpretation, preventing LLM hallucination errors in chart casting.

**Input Parameters:**
| Parameter | Type | Description |
|-----------|------|-------------|
| Year | Integer | Birth year (e.g., 2000) |
| Month | Integer | 1-12 |
| Day | Integer | 1-31 |
| Hour | String/Integer | Chinese 时辰 (子时, 丑时...) or 0-23 |
| Gender | String | "male" or "female" (affects 阴阳 calculation) |
| Calendar | Boolean | True = Solar, False = Lunar |
| Target Date | Optional | For 运限 (大限/流年/流月/流日) calculation |

### 3.2.3 LangGraph Multi-Agent Architecture

The character card conversation system uses LangGraph for orchestration, implemented with a configurable node-edge graph structure stored in MongoDB. The system supports two primary conversation modes: **Chatting** (regular conversation with memory retrieval) and **Venting** (emotional listening followed by Zi Wei analysis).

**Node Types:**
| Type | Purpose | Examples |
|------|---------|----------|

| `condition` | Branching logic | Memory Check, Token Response |
| `process` | Data transformation | RAG Retriever, Context Builder |
| `end` | Output formatting | Output Formatter |

```
│  └─────────────────────────────────────────────────────────┘   │
```

## Appendix A: Zi Wei Dou Shu System Overview

Zi Wei Dou Shu (紫微斗数, Purple Star Astrology) is one of the most sophisticated Chinese astrological systems with over a thousand years of history. It uses the lunar calendar and precise birth time to calculate a person's destiny chart (命盘).

**Technical Implementation:**
The system uses **py-iztro** (v0.3.3), an open-source Python library that faithfully implements traditional Zi Wei algorithms. Key features include:
- Complete 本命盘 (natal chart) calculation
- 大限 (decade cycles), 流年/流月/流日 (annual/monthly/daily cycles)
- Accurate star placement and brightness calculation
- Four Transformations (四化) assignment

**Key Components:**

| Component | Chinese | Description |
|-----------|---------|-------------|
| 12 Palaces | 十二宫 | Life domains: 命宫、兄弟、夫妻、子女、财帛、疾厄、迁移、交友、事业、田宅、福德、父母 |
| 14 Main Stars | 十四主星 | 紫微、天机、太阳、武曲、天同、廉贞、天府、太阴、贪狼、巨门、天相、天梁、七杀、破军 |
| Auxiliary Stars | 辅星 | 左辅、右弼、文昌、文曲、天魁、天钺 |
| Malefics | 煞星 | 陀罗、擎羊、火星、铃星、地空、地劫 |
| Four Transformations | 四化 | 化禄、化权、化科、化忌 |
| Star Brightness | 庙旺陷落 | 庙、旺、得地、平、闲、陷 |
| Five Elements Bureau | 五行局 | 水二局、木三局、金四局、土五局、火六局 |

**Calculation Flow:**
1. Convert solar/lunar calendar and apply true solar time correction
2. Calculate 五行局 based on birth year and gender
3. Place 命宫 and determine 12 palace positions
4. Calculate and place 14 main stars with brightness levels
5. Apply 四化 based on birth year stem
6. Add auxiliary stars and malefics
7. Calculate 大限 ranges (10-year periods)
8. For specific dates, calculate 流年/流月/流日 overlays

## Appendix B: Character Card Conversation Flow

The Character Card system implements a stateful conversation engine with LangGraph orchestration. The flow is dynamically configurable through a JSON-based node-edge definition stored in MongoDB.

**Configuration Schema:**
```javascript
{
  flowId: 'rolecard',           // Unique flow identifier
  flowName: 'AI角色卡对话',      // Display name
  description: '...',           // Flow description
  nodes: [
    {
      nodeId: 'intent_classifier',
      nodeName: '意图分类',
      nodeType: 'start',        // start | condition | process | end
      promptType: 'none',       // none | static | dynamic
      staticPrompt: '',         // Static prompt text
      dynamicSources: [         // Dynamic data sources
        { name: '用户消息', description: '...' }
      ],
      llmEnabled: true,         // Whether this node uses LLM
      llmConfig: {              // LLM configuration
        source: 'ollama',
        model: 'deepseek-r1:14b',
        temperature: 0.3,
        maxTokens: 200
      },
      position: { x: 300, y: 50 }  // Visual editor position
    }
    // ... more nodes
  ],
  edges: [
    {
      source: 'intent_classifier',
      target: 'token_monitor',
      conditionType: 'always',  // always | conditional
      label: ''
    }
    // ... more edges
  ]
}
```

The conversation state includes:
- `messages`: Conversation history (role, content, timestamp)
- `intent`: Current intent classification result
- `tokenCount`: Running token usage counter

- `fortuneAnalysis`: Internal Zi Wei analysis (hidden from user)
- `phase`: Current conversation phase (listening/chatting/analyzing)
